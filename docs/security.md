# Security controls and verification

This is an application security review, not a claim that every possible attack is prevented.

| Attack or risk                                | Controls reviewed or added                                                                                                                                                                                                                                    |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SQL injection                                 | PostgreSQL bound parameters; schema identifier allowlist; SQL injection regression checks.                                                                                                                                                                    |
| Stored/reflected XSS                          | React text escaping, no HTML rendering sinks, restrictive script CSP on API and Vercel static pages; stored chat markup browser regression.                                                                                                                   |
| CSRF, including login/logout CSRF             | Strict SameSite cookies, Origin/Referer and cross-site Fetch Metadata checks; JSON-only nonempty mutation bodies; no permissive CORS.                                                                                                                         |
| Clickjacking                                  | CSP frame-ancestors none and X-Frame-Options DENY, including Vercel static pages.                                                                                                                                                                             |
| Password brute force and credential stuffing  | Existing per-instance IP login limiter plus shared PostgreSQL account counters: 30 attempts per fixed 15-minute window, reset on successful login; generic failed-login responses. Account throttling can temporarily deny legitimate login during an attack. |
| Session theft/fixation/replay                 | Random 256-bit session tokens, SHA-256 hashes stored server-side, HttpOnly/Strict cookies, Secure in production, eight-hour expiry, old presented session revoked on login; account changes and logout revoke sessions.                                       |
| Broken access control / IDOR                  | Server-side roles and active-account checks, per-user notification reads and private-message restrictions; existing negative permission tests. Warehouse parcels are intentionally shared with warehouse staff.                                               |
| Mass assignment                               | Zod schemas reconstruct permitted fields before controllers run; login response allowlists public account fields.                                                                                                                                             |
| Request floods / oversized payloads           | 1000 API requests per minute per IP per instance, 1 MB JSON limit, bounded message history and upload dimensions. General API throttling is not shared across instances and is not a DDoS defense.                                                            |
| Malicious uploads / image decompression abuse | Only JPEG/PNG/WebP, 500 KB, 4096x4096 and single-frame limits; decode and re-encode as resized WebP; no SVG/HTML uploads.                                                                                                                                     |
| Spreadsheet formula injection                 | CSV escaping and formula-prefix neutralization; regression tests.                                                                                                                                                                                             |
| OS command injection / path traversal         | Backup processes use shell:false and argument arrays; server-selected backup artifacts and binaries; static assets stay within build directory. No user-provided command execution.                                                                           |
| SSRF / redirect abuse                         | HA monitor URLs are operator configuration, not request input; production HTTPS checks, redirect rejection and timeouts. Operators must restrict configured endpoints.                                                                                        |
| Sensitive-data disclosure / caching           | API no-store, sanitized parser errors and generic unexpected errors, public login response fields, private environment files excluded from deployment and source control.                                                                                     |
| Dependency / supply-chain vulnerabilities     | npm audit checks full dependency tree; CI rejects high/critical findings. Lockfile plus npm ci. Audit cannot detect every malicious package.                                                                                                                  |
| Race conditions / integrity failures          | Atomic database operations and advisory locking; duplicate tracking rollback, concurrent capacity and single-release dispatch tests.                                                                                                                          |
| Transport / MIME / browser misuse             | Vercel HTTPS/HSTS, nosniff, restrictive CSP, referrer policy; camera self only, microphone/geolocation disabled. Local HTTP remains supported.                                                                                                                |

## Deployment boundaries

Vercel WAF/DDoS rules, MFA for GitHub/Vercel/database accounts, credential rotation, database network restrictions and restore drills require operator configuration. The code does not establish that these account settings are enabled. New production databases reject missing, matching or documented default bootstrap passwords (minimum 12 characters), and demo parcel seeding is disabled by default in production. Existing account passwords are not silently changed: operators must rotate any development credentials still in use. Test reports demonstrate covered behavior, not a penetration-test certification. This change adds migration 009_login_throttling without deleting warehouse records.
